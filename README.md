# CS-255-System-Analysis-Design
Portfolio of system analysis and design work completed for SNHU CS 255, including DriverPass business requirements and system design documents.

# DriverPass Project Reflection

## Project Summary
DriverPass project entailed creating a web-based solution for the client who intended to offer help to the students in preparation for their driving tests. This solution included courses, practice examinations, scheduling of driving lessons, and learning packages. The solution was supposed to enable the secretaries to organize customers' appointments and provide authorized personnel with the relevant information.

## What I Did Well
I had a great performance in the identification of the main requirements of the DriverPass software and structuring them according to the client's needs. For example, I employed various diagrams to explain the process through which the users will interact with the software. I also took into consideration the security of the software, as well as accessibility and cross-device usage.

## What I Would Revise
In case there was any one area that I would like to improve within my project, it is the system design diagram whereby I would ensure that there is consistency in the design of the diagrams and that each design reflects the requirements. There will be additional details in some of the processes such as unavailability and modifications of booking appointments.

## Interpreting and Implementing User Needs
The requirements of the client were understood based on what the clients and employees would need to do. The features that were created included account management, purchasing training packages, taking practice tests, and scheduling driving lessons. The reason why user needs have to be considered is because the system has to be able to solve the problems of the client and be feasible for the users. If not, the system might end up being difficult to use or useless altogether.


## My Approach to Software Design
I believe that the approach to design a software system begins with understanding the requirement and analyzing the problem, based on which a decision regarding the functioning of the system is made. For future projects, I will apply techniques such as evaluating the requirements of the client, finding out who the users of the system are, using use case and activity diagram, and modeling the interaction between the components of the system.
